# 人物工作台 · 使用与开发交接文档

版本：1.3.0  
交付日期：2026-09-09  
适用对象：使用者、后续开发者、接手项目的 AI

2026-09-23 更新：侧栏项目选择框中，对角色卡或世界书项目名称点击右键，会出现对应项目的删除操作；选中后仍需在确认弹窗核对项目名称。点击触发器右键可删除当前项目，手机端继续使用侧栏底部的“删除当前项目”。删除非当前项目时保留正在编辑的项目，删除当前项目时切换到列表中下一项；若全部删完则自动创建空白角色卡。项目与该项目本机快照、临时参考分析和对话材料同时移除。

预设下拉文案现为“自定义创作预设/破甲预设”。该字段属于用户自填文本，已有项目存储的预设内容与自定义名称保持原样，不会因文案更新被覆盖。源码和使用说明以 MIT 许可证公开发布，GitHub 仓库为 `whorebaby123/character-desk`。

## 1. 已确认的产品范围

这是一个个人使用的 SillyTavern 人物设定编辑器。用户以自然语言描述人物需求，选择角色卡或世界书格式；也可以读取已有文件，继续编辑。AI 通过用户提供的 API 工作，同时提供“复制提示词—在其他 AI 生成—粘贴结果”的路径。

新增需求已纳入：用户描述游玩时出现的问题、期望表现及相关对话，系统分析可能原因，提出具体设定修订，展示前后差异，由用户逐项应用。

视觉采用用户色卡中的珊瑚橘为主色，页面与侧栏均为纯白底色，选中状态统一为浅青色（#9bdcdd），世界书标签为明黄（#ffdf32）。保留深蓝文字、海蓝分析及海粉反馈。借鉴 ChatGPT 的侧栏与中央工作区结构：左侧管理项目和条目，中央切换“创作与分析”或“编辑设定”，不再同时挤放三栏。控件缩小间距，正文保持 16px。侧栏可收起，手机端纵向排列。预设默认折叠。

## 2. 快速上手

### 从零创建

1. 点击“新建项目”，选择角色卡或世界书，填写名称。
2. 在“创作与分析 → 创作”填写人物特点及必须保留的设定。
3. 点击顶部“API 设置”，下拉选择服务商与模型，填写密钥，点击“测试连接”；成功后“保存并使用”。
4. 点击“生成人物设定”。请求期间显示等待状态，可以停止。
5. 审核修改理由、AI 补充事实和前后正文，勾选要接受的模块，点击应用。
6. 在“检查”查看基础提示；点击“导出”选择角色卡 JSON 或世界书 JSON。

“打开示例”提供一个独立的林照人物项目，内容为演示创作，可自由编辑。

### 读取已有文件

点击“读取文件”。支持 UTF-8 TXT、Markdown、JSON 和包含标准角色卡数据的 PNG，单文件最大 10 MB。每次读取均建立独立项目，不覆盖原项目。

| 输入 | 行为 |
| --- | --- |
| 角色卡 V1 JSON | 读取主要字段；导出升级为 V2 |
| 角色卡 V2 JSON | 读取字段、备用开场白和内嵌世界书；同格式导出保留其他扩展字段 |
| 角色卡 V3 JSON | 读取可编辑字段，保留 V3 标记及额外字段；不宣称完整 V3 资产支持 |
| SillyTavern 世界书 JSON | 读取 `entries` 对象，编辑各条目正文、名称、关键词、常驻和启用状态 |
| `entries` 数组形式的世界书 | 读取后转换为 SillyTavern 世界书对象格式 |
| PNG 角色卡 | 读取 `tEXt` 中的 `ccv3` 或 `chara` 数据；两者存在时优先 `ccv3` |
| TXT / Markdown | 原文放入当前所选格式的新项目首个模块，不擅自让 AI 改写 |
| 本工具 `.backup.json` | 恢复正文、要求、锁定状态和最近版本，作为独立项目打开 |

PNG 导出当前提供 JSON 数据文件，不重新打包 PNG 头像。普通 PNG 图片会给出“没有角色卡数据”的提示。压缩文本块、iTXt 嵌入、CHARX 和远程 URL 读取不在本版支持范围内。

### 根据游玩反馈修改

1. 先读取要修订的角色卡或世界书。
2. 锁定必须保持原样的模块，并在“创作”里写清硬性要求。
3. 切换到“创作与分析 → 游玩反馈”。
4. 分别填写“实际出现了什么问题”和“你希望怎样表现”。
5. 可在“相关对话或运行信息”中补充信息；也可点击“导入酒馆对话”，读取对话并选中问题消息及前后文。此步骤可跳过。
6. 点击“分析并提出修订”，或复制反馈提示词到其他 AI。
7. 查看诊断、可能的外部因素、每处修改理由与前后内容；选择应用。
8. 导出修改后的 JSON，重新导入 SillyTavern，并在真实游玩中验证效果。

例如，实际问题可以是“刚认识两轮便倾诉秘密”；期望表现可以是“保持礼貌距离，通过共同经历逐渐建立信任”。工具会请求 AI 区分设定不充分、触发问题、模型或外部提示词影响。诊断是建议，不能保证改卡消除所有模型行为。

### 可选：导入酒馆对话

支持 SillyTavern JSONL、JSON 消息数组、含 `messages` / `chat` 数组的 JSON，以及 UTF-8 TXT / Markdown。单文件不超过 10 MB，最多 10000 条消息。TXT 按空行分段，发言者标为未知，不猜测角色身份。

JSONL 的聊天元数据头不会成为对话；读取 `mes` 当前显示的回复，不展开 `swipes` 候选，不发送 `extra` 中的思考和其他元数据。损坏的 JSONL 会提示具体行号。

默认选择能容纳的最近 20 条非系统消息，可按编号范围或逐条勾选，预览每页 50 条。所选证据最多 40000 字符，超出时必须缩小范围，不静默截断。分析提示要求引用 `#消息编号`，区分证据与推测。

只有“游玩反馈”会使用已启用的所选对话；创作、局部改写、检查不会附带它。导入对话和选择范围按项目暂存于当前页面，刷新后清除，不进入项目备份或酒馆导出文件。手动复制反馈提示词时，提示词中同样包含所选证据。

### API 配置、记忆和连接测试

1. 服务商下拉支持 Google AI Studio 的 Gemini 原生、Google OpenAI 兼容、DeepSeek、自定义兼容接口。选定后预填地址和常用模型，模型 ID 也可手动编辑。
2. “读取模型”使用当前密钥获取服务商模型列表；列表读取成功不代表模型生成成功。
3. “测试连接”用当前模型、认证方式及生成参数实际请求一条短回复，只有收到有效正文才显示成功。测试可能产生调用费用；重新打开页面不会自动发起付费测试。
4. 点击“保存并使用”保存地址、模型及参数。默认勾选“记住此设备的密钥”，下次打开自动恢复；可取消，或点击“忘记已保存密钥”。密钥保存在当前浏览器站点数据中，不跨设备同步，不放入项目备份。
5. 配置恢复不显示成已验证连接；成功状态只对应本次页面中实际测试或生成成功的那份配置。修改模型、Key 或参数后需要重新验证。

| 选项 | 实际处理 |
| --- | --- |
| Key / Authorization | 支持原始 Key、Bearer 值和整行认证头；密钥内容视为不透明字符串，不要求以 `AIza` 或 `sk-` 开头 |
| 自动认证 | Gemini 原生用 `x-goog-api-key`；兼容接口用 `Authorization: Bearer` |
| 手动认证 | 可指定 Bearer、原始 Authorization、`x-goog-api-key`、`x-api-key` 或 `Key` 头 |
| 思考强度 | 选项随接口与模型变化；默认不传，Gemini 原生映射为 thinkingConfig，兼容接口传 reasoning_effort |
| Gemini 2.5 思考 | 低/中/高映射到 1024 / 8192 / 24576 budget；2.5 Flash 可选关闭，2.5 Pro 不提供关闭 |
| 温度 / Top P | 范围分别为 0–2 / 0–1，留空不发送；DeepSeek 思考模式下不发送并说明原因 |
| Top K | 正整数 1–1000，留空不发送；Gemini 原生和自定义接口可填写，Google 兼容与 DeepSeek 禁用；具体模型仍可能不支持 |
| 最大输出 | 512–65536，默认 8192；模型自身上限以服务商响应为准 |

Google 地址：原生 `https://generativelanguage.googleapis.com/v1beta`；兼容 `https://generativelanguage.googleapis.com/v1beta/openai`。自动去除重复的 `chat/completions` 等完整终点后缀，避免重复拼接。切换服务商会清空当前 Key，需要填写对应服务的密钥。

本次兼容修订参考了用户上传的请求附件及站点错误日志。附件使用 Google 兼容地址，包含 `key` 字段，模型为 `gemini-3.8-flash`。旧日志只显示快速返回 400，不能仅凭这些信息认定原因为认证头。1.2.0 增加原生接口、字段别名、认证选择和分阶段错误码，并改用 AbortController 超时处理。1.2.1 在与线上同源的 workerd 引擎中复现了真正的请求失败原因：Workers 不支持 `redirect: error`，请求在发出前就抛出 TypeError。现改用 `redirect: manual`，遇到 3xx 明确拒绝且不转发密钥。原有 Node 模拟测试未覆盖这一运行环境差异，现增加 workerd 回归测试。

### 创作预设

内置“均衡人物设定”“人物一致性”“含蓄文学表达”“最小修订”。可直接编辑，或导入 TXT / Markdown / JSON（`name` 与 `text`，也接受 `prompt`）；文件最多 100 KB，正文最多 20000 字符。预设随项目、备份及跨格式转换保存，不自动写入酒馆导出的角色系统提示字段。

这些预设控制写作风格和修订侧重点；本版未内置“打工猫”或其他绕过模型安全机制的破限指令。任意 SillyTavern 复杂预设 JSON 不在完整导入范围内，需先整理为上述简单格式。

### 参考文本：分析人物与关系，再套用设定

入口：左侧“创作与分析” → 中央“文本分析”。

1. 粘贴参考文字，或导入 UTF-8 TXT / Markdown。导入上限 10 MB，单次分析最多 80000 字符；超限时保留已读取的原文，让用户手动缩小片段，不静默截断或假装分析了全文。
2. 选择“人物形象与关系”“只分析人物形象”或“只分析人物关系”。可填写重点人物或组合、额外要求；关系视角支持由文本决定、恋爱/亲密关系、日常交流、友情、亲情、对立/竞争及自定义说明。
3. 点击“开始分析”。此步骤只分析参考文本与用户要求，不发送当前世界书、不改动项目、不附带游玩对话或创作预设。缺少 API 时可使用“手动分析”，复制提示词后粘贴 JSON。
4. 分析结果分别列出人物形象、动机、语言与行为，以及关系互动、发展条件和相处方式。每项可展开短摘录，程序核对段落编号和摘录是否匹配；不匹配的证据明确标记。摘录匹配不等于分析结论必然成立。
5. 勾选想参考的人物或关系。在“如何带入当前项目”里填写原文人物到当前人物的映射、要借用的特点、要保留或排除的内容。例如“林照对应陆川，陈望对应周宁，借用两人的日常相处方式，保留现有身份经历”。
6. 点击“生成套用建议”。仅把选中的分析、用户映射要求和当前设定交给模型，要求转化行为与关系模式，避免照搬姓名、背景、剧情或长段原文。也可走“手动套用”路径。
7. 使用原有差异审核弹窗逐项接受；锁定、版本快照、项目内容变化检查仍生效。应用后自动切回“编辑设定”，再按需要导出世界书或角色卡。

参考文本与分析草稿按项目暂存在当前页面，切换标签或项目可继续使用；刷新后清除。分析结果可下载 JSON 供留存；本版不提供独立分析 JSON 的重新导入。已应用的设定会正常自动保存及备份。修改参考原文或分析选项时清除旧分析，避免将旧结论套用于新材料。最多解析 30 个人物、60 组关系，每项最多 4 条短证据。

### 手动生成路径

“复制提示词 / 粘贴结果”用于完整生成；“手动修改当前模块”用于局部修改。复制弹窗中的完整提示词，到任意支持文本生成的服务生成，再把返回的 JSON 粘贴回来。

若返回的是普通文字，可点击“作为当前模块文字”，形成一条替换建议，仍需审核后应用。格式错误的模型原文会保留在粘贴框内，不直接覆盖设定。

### 保存、恢复和备份

- 当前项目在输入停止约 350 毫秒后保存到浏览器 localStorage，离开页面时也尝试写入。
- 应用建议、删除条目、恢复版本和新增条目前会记录快照；也可手动保存快照。
- 每个项目最多保留最近 20 个快照。手动输入不会每个字符都产生版本。
- 项目备份包含当前项目和版本，不包含 API 密钥。
- 数据不跨浏览器、不跨设备自动同步。清理站点数据会删除本机项目。
- 本机存储损坏时暂停自动覆盖，提供下载原始数据入口。空间不足会明确提示备份。
- 多个标签页同时编辑同一项目没有冲突合并机制；请在一个标签页编辑。

## 3. 导出与字段映射

新角色卡采用 V2。读取 V3 后保持 V3 标记；读取 V1 后按 V2 输出。没有使用模型生成完整的文件结构，文件结构由程序构造。

| 编辑模块 | 角色卡 `data` 字段 |
| --- | --- |
| 项目名称 | `name` |
| 身份、外貌与经历 | `description` |
| 性格、动机与行为 | `personality` |
| 场景与人物关系 | `scenario` |
| 开场白 | `first_mes` |
| 示例对话 | `mes_example` |
| 角色系统提示 | `system_prompt` |
| 历史后指令 | `post_history_instructions` |
| 作者备注 | `creator_notes` |
| 备用开场白 | `alternate_greetings` |
| 内嵌世界书条目 | `character_book.entries` |

角色卡中的创作者、标签、扩展字段等没有单独的编辑界面，读取后保留。`{{user}}`、`{{char}}` 和 `{{original}}` 等宏保持为文字，不由网页执行。

世界书条目可编辑 `content`、`comment`、`key`、`constant`、`disable`。已有的次级关键词、选择逻辑、顺序、位置、概率、深度和扩展字段在同格式导出时保留。导出为新增条目分配不重复的 UID。

跨格式转换会重组内容，不等价于保留全部运行语义：

- 角色卡转世界书：将有正文的模块拆成条目，默认人物名作为触发词；不转换作者备注、系统提示和历史后指令。
- 世界书转角色卡：汇总条目到角色描述，并附上内嵌世界书；开场白和示例对话需补充。内容可能重复占用上下文，可按使用场景精简。
- 跨格式转换不复制所有原格式扩展设置；原项目不会被转换操作覆盖。

格式参考：

- [Character Card V2 Specification](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)
- [SillyTavern World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)
- [SillyTavern Character Design](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)

### 核心数据模型

`Project` 包含 `id`、`kind`、`name`、`brief`、`constraints`、`sections`、`original`、`source`、`updated` 及可选的 `creationPreset`。

`Section` 包含稳定 `id`、`label`、`text`、`locked`；世界书条目另有 `keys`、`constant`、`disabled` 和 `raw`。

`original` 保存原文件结构，`raw` 保存原条目字段，用于同格式导出时保留未编辑字段。它们不会在每次输入时直接改变；导出将当前编辑内容合并到原结构中。

本机键名：

- `character-desk:workspace:v1`：项目列表、当前项目 ID、版本记录。
- `character-desk:api:v1`：内部 version=2，保存接口类型、地址、模型、认证方式、生成参数与记忆开关；开关开启时包含密钥。兼容迁移旧配置。

本工具备份格式标记为 `character-desk-backup`。导入后分配新项目 ID，以免覆盖同名项目。

### AI 修改协议

返回格式：

```json
{
  "summary": "本次诊断或修改概要",
  "warnings": ["需要注意的不确定性或外部因素"],
  "additions": ["AI 新增的人物事实"],
  "patches": [
    {
      "id": "personality",
      "text": "该模块修改后的完整正文",
      "reason": "为何这样改，以及对应哪项反馈"
    }
  ]
}
```

世界书修改可以额外给出 `keys` 和 `constant`。世界书新条目使用唯一 `new:` 前缀 ID，并提供 `label`。角色卡 AI 修改只能引用已有模块；要增加内嵌条目，先在界面点击添加。

修改保护分三层：

1. 提示词要求遵守硬性条件、锁定状态和局部修改范围。
2. 解析器拒绝未知 ID、重复 ID 和越过当前模块的局部修改。
3. 程序应用时再次跳过锁定模块，并比对生成时的项目指纹。若正文后来已改变，旧建议拒绝应用，避免覆盖较新内容。

事实与性格逻辑是语义问题，无法通过 JSON 校验保证。新增事实会列出供审核；锁定保护则由程序强制执行。

### API 请求

浏览器向本站 `POST /api/generate` 发送配置字段、`key` 和 `prompt`。`POST /api/connection` 使用同一配置，另加 `action: "test"` 或 `"models"`。

兼容接口采用 `messages`、`stream: false`、`max_tokens`，可附带支持的采样参数。Gemini 原生采用 `contents` 和 `generationConfig`，请求 `models/{model}:generateContent`。当前不做逐字流式显示，完成后一次显示建议。超时 90 秒；用户可停止等待，但服务商可能继续处理和计费。

服务端检查 Origin；只接受 HTTPS 公网域名形式、443 端口、无 URL 内嵌账号及查询参数，不跟随重定向。请求正文最多 600000 字节，上游响应最多 2 MB。URL 检查不是完整 DNS 重绑定防御。本站不记录密钥、不缓存响应，不返回完整上游响应体；会提取并脱敏上游错误信息，最多 900 字符。

成功生成返回 `{text, notes}`；错误返回 `{error, code, stage}`。例如 `INVALID_CONFIGURATION`、`UPSTREAM_400`、`UPSTREAM_401`、`NETWORK_ERROR`、`TIMEOUT`、`OUTPUT_TRUNCATED`、`EMPTY_CONTENT`。上游错误在站内通常返回 HTTP 502，实际服务商状态保留在错误码及提示中。

部署依赖 Sites 私人访问控制。迁移到普通公网主机时，需要增加身份认证、速率限制及严格的出站地址策略；Origin 检查本身不等于身份认证。

接口参考：

- [Gemini OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai)
- [Gemini generateContent](https://ai.google.dev/api/generate-content)
- [Gemini thinking](https://ai.google.dev/gemini-api/docs/thinking)
- [DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/)

## 5. 开发与运行

此交付环境使用 Node.js 24.19.0。维护时使用 Node.js 24 和 npm；项目构建脚本需要 Bash 与 GNU timeout，Windows 建议在 WSL2 中运行。无需在源码或环境变量中预置个人 API 密钥。

```bash
npm ci
npm run dev
```

打开开发命令实际输出的本地地址。若在 ChatGPT Work 中继续维护，遵循 Sites 技能的安装、构建、预览和发布流程，不自行创建第二个 Site。

验证命令：

```bash
npm run typecheck
npm run lint
npm run test:unit
npm test
```

`npm test` 会先构建，再执行数据、Node Worker 测试和真实 workerd 引擎测试。Worker 测试的上游响应由测试替换，不需要真实 API 密钥，不会产生模型调用费用。

构建输出为 `dist/server/index.js` 及客户端资源。发布必须保留 `.openai/hosting.json` 的 `project_id`，将对应源码推送后再保存并部署相同构建版本。

## 6. 验证状态与边界

交付检查覆盖：

- 34 项单元测试：原有数据与格式 10 项、对话证据 8 项、认证/参数/预设及协议 11 项、人物与关系分析/迁移 5 项。
- 8 项构建后 Worker 测试：中文首页、同源限制、配置验证、兼容生成、错误处理、实际测试路由、原生路由及模型列表。
- 4 项真实 workerd 引擎测试：原生连接、兼容连接、读取模型、拒绝重定向；服务商为进程内固定响应，无联网或模型费用。
- TypeScript 类型检查、业务代码静态检查及生产构建。

服务商响应使用模拟数据；未使用用户密钥完成真实模型调用，因此不能宣称用户账户认证已验证或原先的 400 已在真实请求中消失。未进行真实 SillyTavern 导入及游玩回归，也未执行浏览器点击或截图测试。网页中的“测试连接”可对当前密钥、模型和参数完成实际验证。

当前功能边界：

- 输出为 JSON，不重新生成带头像 PNG；不导入 CHARX。
- 反馈草稿、未应用建议和手动粘贴框目前只保留在当前页面，刷新后会丢失；已应用正文及版本会保存。
- 同格式保留次级关键词、深度等高级设置，但没有它们的专用编辑控件；AI 可看见主要触发设置，自动补丁目前只调整正文、主关键词与常驻。
- 世界书条目最多读取 1000 个；整本内容过长可能超出模型上下文或本站请求长度限制，需精简项目后再生成。
- 不保证模型行为绝对服从设定；反馈修改后仍需真实对话验证。

## 7. 继续开发建议

优先使用用户的一张真实角色卡、一本真实世界书和一段问题对话，完成真实模型生成与 SillyTavern 导入回归，确认字段保留及反馈修订效果。

之后可按实际需求迭代：将反馈草稿和诊断记录加入备份；增加高级触发参数的可审核补丁；支持流式响应和更多模型协议；将大型页面拆成独立业务组件；如有跨设备需求，再引入账户隔离的数据库同步。以上均未伪装成本版已完成功能。

### 触发词建议

在“编辑设定”中选中世界书条目（或角色卡内嵌世界书条目），点击触发词输入框旁的“建议触发词”。使用当前 API 配置，仅发送当前条目名称、正文与已有触发词。展示候选词及理由，勾选后追加，保留原有触发词，并自动保存修改前快照。已锁定条目不可操作；条目变化后旧建议失效，需重新生成。常驻条目也可准备触发词，切换为按需触发时使用。

支持停止请求、重新建议、复制提示词及粘贴外部 AI 的 JSON 结果。建议是临时状态，切换条目或刷新后清除；已添加词正常本机保存并导出。单条目最多 8 万字符，解析结果去重、排除已有词及正则形式词语，最多展示 12 个候选。模型建议仍需用户判断是否容易误触。

实现：`components/desk/trigger-suggestions.tsx`、`lib/trigger-words.ts`，沿用现有生成接口，无新增服务商配置或后端数据存储。
